# GPT‑5.1のOCR性能を、Azure環境でGPT‑4oとガチ比較してみた

最新のGPT‑5.1が、画像中の文字をどこまで正確に読み取れるのかを、GPT‑4oとの比較という形で検証した結果をまとめる。
Azure AI Document Intelligenceとの組み合わせも含め、実利用を想定した観点で◎・〇・×評価を付けた。

## 検証の狙い

- GPT‑5.1はGPT‑4oと比べて、OCR精度や実用性がどの程度向上しているのかを把握する。
- Azure上で、「Azure AI Document Intelligence＋GPT‑5.1」という構成が、実務ワークフローとしてどこまで使えるかを確認する。


## 検証環境と前提

- クラウド:
    - Microsoft Azure 上に検証用リソースを作成
    - Azure AI Document Intelligence（レイアウト / OCR機能）を利用
- モデル:
    - 最新モデル: GPT‑5.1
    - 比較対象: GPT‑4o
- 入力形式:
    - 対象ドキュメントをAzure AI Document Intelligenceに通し、Markdown形式のOCR結果を事前取得
    - そのMarkdownをGPT‑5.1およびGPT‑4oに入力し、「OCR結果の再解釈・補正・構造化」を行わせる


## 検証シナリオ

今回の検証では、実務で遭遇しがちな以下5パターンを対象とした。

1. 印刷された資料
2. 手書きの文字が混在する領収書・請求書
3. ハンコとかぶっている箇所がある領収書・請求書
4. 選択肢に対して丸で囲う形で回答する資料（マークシート的なフォーマット）
5. 上下逆さの資料（回転されていないスキャン画像など）

各シナリオで同一の元資料を用意し、Azure側で一次OCRしたMarkdownをGPT‑5.1とGPT‑4oの両方に入力して比較する。

## 評価観点

- 文字認識の正確さ
    - 誤字・脱字、専門用語・固有名詞の取りこぼし
- 文脈理解・補正能力
    - OCRの欠損や読みにくい箇所を文脈からどこまで補正できるか
- コスト（トークン課金）
    - GPT‑5.1とGPT‑4oのトークン単価、処理量が増えたときの月額イメージ

各観点について、◎（実運用OK）・〇（条件付きで利用可）・×（実運用は厳しい）で評価する。

## Azure AI Document Intelligenceとの連携方法

検証フローは「Azure側で一次OCR → GPTモデル側で後処理」という構成を前提とする。

- 手順のイメージ:

1. 対象ドキュメントをAzureにアップロード
2. Azure AI Document Intelligenceのレイアウト／OCRモデルで解析
3. 出力されたMarkdown形式の結果を取得
4. MarkdownをGPT‑5.1およびGPT‑4oに入力し、再構造化・誤り補正・要約などを実行
- この構成を取ることで、AzureのOCRとGPT‑5.1/4oの文脈理解・生成能力を組み合わせたパイプラインを組める。


## ベンチマーク条件と評価方法

- 入力データ:
    - 上記5シナリオそれぞれで複数パターンの実データを用意（特に領収書・請求書は形式違いを含める）
    - 同一のMarkdown OCR結果をGPT‑5.1とGPT‑4oにそれぞれ入力
- プロンプト:
    - 文字起こしの正確さ、レイアウト再現、表の構造化、金額抽出などを同一プロンプトで指示
    - 必要に応じて英語プロンプトも試し、日本語プロンプトとの差を記録する
- 評価方法:
    - 元ドキュメントと出力結果を目視照合し、観点ごとに◎・〇・×を付与
    - 応答時間や安定性、想定ボリューム時のコスト感もメモしておく


## 各観点ごとの評価イメージ

ここは、実測結果を書き込むための「テンプレ＋コメント」の位置付け。

### 文字認識の正確さ

- GPT‑5.1:
    - 印刷資料では誤字・脱字がさらに減り、GPT‑4oよりも安定した認識が期待できる。
    - 領収書・請求書の住所や会社名など、やや崩れた文字に対する補正精度も向上しているかを確認する。
- GPT‑4o:
    - すでに高精度だが、ハンコや手書きが重なった箇所では誤認識が出るケースもあるため、どの程度の頻度かを測る。


### 文脈理解・補正能力

- GPT‑5.1:
    - かすれた文字や、部分的に読めない項目を、前後の文脈から自然に補完できるかを確認する。
    - 選択肢に丸を付ける形式の資料で、「どの選択肢が選ばれているか」をテキストで明示できるかも評価ポイントにする。
- GPT‑4o:
    - 文脈補完は可能だが、丸付き選択肢など「位置情報も絡む理解」で、GPT‑5.1との差が出るかを整理する。


## コスト・金額面の比較

ここでは、トークン課金モデルを前提に、概算のコスト感を整理する。

- モデル単価の傾向:
    - GPT‑5.1は、同等クラスのGPT‑4系モデルより入力・出力トークンあたりの単価が安いとされており、同じ処理量ならGPT‑4oより費用を抑えられるケースがある。
    - GPT‑4oはフラッグシップモデルとして、依然として高性能だが、単価面ではやや高めに位置付けられることが多い。
- 想定シナリオ:
    - 月間で数万〜数十万ページ規模の帳票を処理する場合、同じプロンプト設計であればGPT‑5.1に寄せた方が総トークン数と単価の両面でコストを抑えられる可能性がある。
    - 逆に、既存システムがすでにGPT‑4o前提で組まれており、追加開発コストを抑えたい場合は、当面GPT‑4oを継続利用しつつ、ボリュームの大きいバッチ処理のみGPT‑5.1に切り替える、といったハイブリッド構成も考えられる。

※ 実際の記事では、当時点の公式価格表を元に「1枚あたりの概算単価」「月1万枚処理した場合の概算料金」などを簡単な表で追記すると、読み手がイメージしやすくなる。
